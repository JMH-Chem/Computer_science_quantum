# Quantum Lab

분자와 작은 결정의 양자화학 계산을 실행하고, 수렴 과정과 전자구조를 브라우저에서 탐색하는 로컬 연구·학습 프로그램입니다. Python/PySCF 계산부와 React 화면을 사용합니다. 외부 AI 서비스나 GPU가 필요하지 않습니다.

**SCF 반복은 실제 시간이 아닙니다.** 화면은 계산 중 에너지 상승과 진동도 그대로 보여줍니다. TDDFT의 여기 에너지·전이 세기와 교육용 S1→S0 모식도는 실제 들뜬 상태 이완 궤적이나 수명 계산과 구분합니다.

첫 예제는 H₂, H₂O, 포름알데히드, 다이아몬드입니다. 기본 기저·격자·k점은 작은 예제를 빠르게 탐색하기 위한 값입니다. 연구에 사용할 때는 기저, 수치 격자, k점과 수렴 허용오차를 별도로 검증해야 합니다.

금속·부분 점유 결정, 표면·결함, 셀 최적화, 주기계 들뜬 상태·상관 방법, GW/BSE, xTB 연결과 실제 비단열 동역학은 현재 지원 범위에 포함하지 않습니다. 전체 조사 범위와 구현·검증 범위는 [방법론 안내](docs/methods.md)에 정리했습니다.

상관 계산의 저장 오비탈·밀도·원자 전하는 **RHF 기준**이며 상관 에너지와 구분합니다. EOM-CCSD는 여기 에너지를 제공하고 전이 세기·NTO는 제공하지 않습니다. FCI/CAS에는 행렬식 수·메모리 추정 한계가 있고 NEVPT2는 활성 궤도 8개 이하로 제한합니다. 활성 공간을 자동으로 화학적으로 적절하게 선택했다고 주장하지 않습니다.

## 설치와 실행

Python **3.12**, Node.js **24 LTS**, npm, [uv](https://docs.astral.sh/uv/)가 필요합니다. 저장소 루트에서 실행합니다.

```bash
uv sync --frozen
npm --prefix frontend ci
npm --prefix frontend run build
uv run quantum-lab serve
```

같은 절차를 묶은 `./scripts/setup.sh`와 실행용 `./scripts/start.sh`도 제공합니다. 예를 들어 `./scripts/start.sh --port 8001 --data-dir /path/to/data`로 포트와 저장 위치를 지정할 수 있습니다.

브라우저에서 로컬 서버의 8000 포트로 접속합니다. 계산과 데이터는 사용자 컴퓨터에 남습니다. 프런트엔드 자산도 로컬에서 제공하므로 매번 외부 CDN에서 시각화 코드를 가져오지 않습니다.

기본 데이터 폴더는 실행 위치 아래 `.quantum-lab/`입니다. 다른 위치에 보관하려면 실행 전에 지정합니다.

```bash
export QUANTUM_LAB_DATA="$HOME/quantum-lab-data"
uv run quantum-lab serve
```

같은 데이터 폴더에 서버를 여러 개 실행하지 마세요. 계산 자원은 작업당 스레드 수와 메모리 예산으로 조정합니다. PySCF 메모리 설정은 운영체제 수준의 강제 제한이 아니므로 실제 사용량은 설정값보다 클 수 있습니다.

### Windows WSL2

WSL2의 Ubuntu 환경 안에 저장소와 Python·Node 도구를 설치한 뒤 위 명령을 실행하고, Windows 브라우저에서 접속합니다. 대량의 임시 파일 입출력을 줄이려면 저장소와 계산 데이터를 WSL Linux 파일시스템에 두는 편이 좋습니다.

이 저장소는 WSL2를 목표 환경으로 문서화하지만 **현재 실제 Windows WSL2에서 설치·실행을 검증했다고 주장하지 않습니다.** Linux에서 통과한 검증과 WSL2 확인 항목은 [검증 기록](docs/validation.md)에 구분합니다. 네이티브 Windows 실행도 별도 지원 검증 대상입니다.

## 첫 계산

1. 예제 목록에서 H₂ 또는 H₂O를 선택합니다. 입력 구조와 기저·방법을 확인합니다.
2. 계산을 실행하고 에너지와 수렴 지표를 확인합니다. 반복 번호는 계산 알고리즘의 단계입니다.
3. 수렴 후 결과를 열어 밀도나 특정 오비탈의 등가면을 생성합니다. 3D 격자는 요청 시 별도 계산하므로 생성 시간이 걸릴 수 있습니다.
4. 포름알데히드 TDA/TDDFT 예제로 여기 상태와 흡수 스펙트럼을 확인합니다. 스펙트럼의 폭을 바꾸는 것은 표시 설정이며 계산된 여기 에너지와 oscillator strength를 바꾸지 않습니다.
5. 다이아몬드 예제로 전환하여 단위격자, SCF, 밴드 구조를 확인합니다. Γ점 결과와 k점 격자 계산의 차이는 수렴 검토의 출발점입니다.
6. 계산 조건을 바꿔 새 작업으로 실행한 뒤 결과를 비교합니다. 각 작업의 입력과 결과가 독립적으로 보존됩니다.

분자 오비탈은 비제한 계산에서 α/β 성분을 선택합니다. NTO 등가면은 선택한 여기 상태의 가장 큰 가중치 쌍을 제공합니다. 주기계에서는 가상퍼텐셜로 제거된 핵심 전자를 포함하지 않는 가전자 밀도를 표시하며, 주기계 오비탈·NTO 등가면은 제공하지 않습니다.

파일에서 분자는 XYZ, 결정은 CIF를 가져올 수 있습니다. 좌표와 격자 길이의 단위는 Å입니다. 스핀 입력은 `Nα − Nβ`이며 다중도 자체가 아닙니다. 잘못된 전하·스핀이나 지원하지 않는 기저 조합은 오류 내용을 확인하고 수정해야 합니다.

학습 보기는 의미와 해설을 함께 보여주고, 전문가 보기는 기저·함수형·수치 조건을 자세히 조정합니다. 두 보기에서 같은 작업의 계산 결과는 동일합니다.

## 학습 실험

상단 **학습 실험**에서 기저를 바꿀 때 에너지가 어떻게 달라질지 예상하고 **기저 3개 비교 시작**을 누릅니다. 같은 물 구조·RKS/PBE·적분 격자·SCF 기준에서 STO-3G, def2-SVP, def2-TZVP 계산을 차례로 실행합니다.

표와 그래프에서 전체 에너지, 바로 이전 기저와의 ΔE, 기저 함수 수, SCF 반복 수, 실행 시간과 최대 메모리를 확인합니다. **자세히**를 누르면 해당 계산의 SCF와 전자밀도를 탐색할 수 있습니다. 실험 이력은 다시 열 수 있고 JSON·CSV로 내보낼 수 있습니다. 응답이 끊긴 시작 요청을 재전송해도 같은 실험이 중복 생성되지 않습니다.

SCF 수렴은 기저 수렴이나 실험값의 정확도를 보증하지 않습니다. 비교에 필요한 조건과 최종 수렴이 확인되지 않은 에너지는 비워 두며, 중간 계산이 실패하면 그 앞뒤의 ΔE를 임의로 연결하지 않습니다.

## 상관·진동·재료 물성 탐색

분자 단일점에서 MP2·CC·CI·CAS 등을 선택하면 **전자 상관** 탭에서 기준 에너지, 상관 에너지와 최종 수렴을 확인합니다. 원자 전하와 쌍극자는 **물성·전하** 탭에 있습니다. EOM-EE-CCSD는 CCSD 바닥상태 위 singlet 여기 에너지를 별도로 보여 줍니다.

진동·열화학은 먼저 HF 또는 지원 DFT로 구조를 최적화한 뒤 **최종 구조로 새 계산**을 눌러 조화 진동 작업을 선택하는 흐름이 유용합니다. IR을 요청하면 실제 변위 구조의 SCF 쌍극자를 계산하므로 시간이 더 걸립니다. 정상 모드의 이동은 임의 진폭의 모식도이며, 허수 모드는 음수 진동수로 표시합니다. 정지점이 아니거나 0 이하의 진동 모드가 있으면 RRHO 열화학 값은 제공하지 않습니다.

결정의 DOS는 균일 SCF k점 격자의 값이며, 밴드 경로에서 나온 점을 균일 가중치로 섞지 않습니다. 상태 수·전자 수 적분과 Gaussian 표시 폭을 함께 확인할 수 있습니다. 밴드의 에너지 기준과 DOS의 에너지 기준은 표시된 VBM 정의를 따릅니다.

계산의 **보고서**는 외부 서비스 없이 인쇄할 수 있는 HTML입니다. **재현 ZIP**에는 입력·결과·이벤트·기저·산출물과 SHA-256 목록이 들어갑니다. 실행 중인 작업의 파일 묶음은 종료 후 제공합니다.

```bash
uv run quantum-lab examples

```

명령행 계산은 기본적으로 `.quantum-lab-cli/`에 보관합니다. `--data-dir`로 위치를 바꿀 수 있습니다. 같은 데이터 폴더를 사용하는 서버가 있거나 미완료 작업이 남아 있으면 임의로 재실행하지 않습니다. 종료 코드는 성공 0, 실패·잘못된 입력 1, 미수렴 2, 사용자 중단 130입니다.

### 화면을 포함한 설치 패키지

```bash
npm --prefix frontend run build
uv run python scripts/package_release.py
```

`dist/`의 새 버전 폴더에 wheel, `requirements.lock.txt`, 소스·자산 SHA-256 manifest를 만듭니다. 기존 패키지를 덮어쓰거나 외부로 업로드하지 않습니다. 이 세 파일을 다른 Linux 환경으로 옮긴 뒤 Python 3.12 가상환경에서 설치할 수 있습니다.

```bash
uv venv --python 3.12 .venv
uv pip sync --python .venv/bin/python --require-hashes requirements.lock.txt
uv pip install --python .venv/bin/python --no-deps quantum_lab-0.3.0-py3-none-any.whl
.venv/bin/quantum-lab serve
```

wheel에는 화면 자산이 들어 있으므로 설치한 컴퓨터에서 Node.js로 다시 빌드할 필요가 없습니다. Python 의존성은 별도로 설치하며, 오프라인 설치는 해당 플랫폼의 의존성 파일이나 캐시도 필요합니다. 실제 Windows WSL2 검증 여부는 위 설치 안내와 별도로 확인하세요.

## 작업 기록과 재현성

- 브라우저를 닫았다가 다시 열어도 서버가 실행 중이면 작업 기록과 진행 상황을 다시 확인할 수 있습니다.
- 서버 종료와 컴퓨터 종료 후에는 실행 중 프로세스가 유지된다고 가정하지 않습니다. 중단 상태와 남아 있는 데이터로 판단합니다.
- `unconverged`는 성공과 다릅니다. 중간 그래프가 있어도 수렴한 물성값으로 사용하지 마세요.
- 작업별 입력 JSON, 엔진 버전, 기저 정의·출처, 최종 결과, 이벤트와 로그를 함께 보관합니다.
- v0.3의 새 작업은 시작 시점의 앱·Python·의존성 버전과 Python 소스 SHA-256을 `environment.json`에 보존합니다. 이미 계산한 과거 작업에는 나중의 버전을 소급 기입하지 않습니다.
- JSON은 입력·결과 보관, CSV는 수렴 이력 분석, XYZ/CIF는 구조, CUBE는 밀도·오비탈 등가면 재사용에 적합합니다.
- 결과 파일과 체크포인트는 현재 설치한 엔진 버전에 의존할 수 있습니다. 다른 버전에서 재계산할 때는 새 작업을 만들고 조건을 비교합니다.

로컬 서버는 루프백 주소를 기본으로 사용합니다. 사용자 계정·원격 인증·공유 서버 운영 기능을 갖춘 서비스는 아닙니다. 연구실 네트워크에 공개하려면 별도의 인증과 운영 설계가 필요합니다.

```bash
npm --prefix frontend run build
```

실제 과학 계산 테스트는 CPU 시간이 필요합니다. 테스트 명령, 수치 허용오차, 브라우저 검증과 미검증 항목은 [검증 기록](docs/validation.md)을 기준으로 확인하세요.

별도의 Psi4 환경을 사용한 선택적 독립 비교는 [검증 환경 안내](validation/README.md)를
따릅니다. 앱의 필수 의존성은 늘리지 않으며, 같은 BSE 기저의 HF·MP2·CCSD와
서로 다른 격자를 명시한 PBE 비교를 재현할 수 있습니다.
