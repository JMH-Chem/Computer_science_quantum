# 검증 기록과 재현 절차

이 파일은 실행한 검증과 앞으로 실행할 항목을 구분한다. 테스트 코드가 존재하거나 설치 명령이 성공했다는 사실만으로 수치 계산과 화면 동작을 검증했다고 표시하지 않는다.

## v0.3.1 문헌 비교 후 재검증

2026-11-14(한국 시간), 문헌 비교에서 발견한 응답·주기계 오류를 수정하고 Linux에서
전체 Python **369개를 280.54초**, 실제 Chromium **19개를 281.68초**에 통과했다.
추가한 k점 비교 판정 검사 5개를 포함한 문헌 실행기 검사 **32개도 별도 실행에서
2.28초에 통과**했다. 최종 수집되는 서로 다른 Python 검사는 **374개**이며,
374개 전체를 한 번에 측정한 시간으로 합산하지 않는다. 실패·건너뜀은 없었다.
Starlette의 httpx deprecation 경고 1개가 있다.

- 물 EOM-CCSD의 출판값 재현, 포름알데히드·S22B·다이아몬드의 조건별 평가는
  [문헌 비교 보고서](literature-validation.md)에 실제 수치·출처·한계를 기록했다.
  공개 CLI 9개 모두 수렴 완료했지만, 다이아몬드의 3³→4³ k점 변화 0.0311 eV는
  선언한 0.025 eV 기준을 넘었다. SCF 완료와 물성의 k점 수렴을 구분한다.
- 회귀 검사는 대칭 영역에 따른 낮은 상태 누락, 작은 양의 응답 고유값 필터,
  실제 GTH-DZVP의 제거 슬롯·DOS 상태 수와 전자 수 보존을 포함한다.
- 브라우저 19개는 실제 분자·결정·응답·상관·진동·학습 실험·취소·재접속·내보내기와
  첫 H₂ 계산을 확인한다. 조건 불일치·실패 데이터 표시 등 일부 검사는 명시적으로
  UI 자료를 사용하며 수치 계산 검증으로 세지 않는다.
- 별도로 실제 GTH-DZVP k2 저장 결과를 읽기 전용 화면 자료로 사용해, 밴드 26개
  곡선의 제거 슬롯 13개가 원본과 같은 빈 구간으로 표시되는지 확인했다. DOS 적분
  50.5 상태·8전자와 안내도 확인했고 원본 해시·저장 데이터는 유지됐다. 이 표시는
  추가 수치 계산이나 20번째 자동 회귀 시나리오로 합산하지 않는다.
- TypeScript·Vite, Ruff, 변경 프런트엔드의 Prettier와 diff 검사가 통과했다.
  Vite의 상위 3Dmol 파일에 대한 eval 경고는 남아 있다.
- 화면을 포함한 **0.3.1 wheel**을 새 Linux 가상환경에 잠금 의존성 42개와 설치했다.
  저장소 밖 소스 23개의 해시, 실제 H₂·다이아몬드 계산과 HTTP 자산을 확인했다.
  [설치 검증 기록](package-validation-v031.json)의 wheel SHA-256은
  `f299bf08ff3bc3b13c2d0207ed547c9016d162cba0e53cb5be8e192930666429`다.
- [일반 사용자 검토](layperson-review.md)는 전문가의 인지적 점검과 자동 화면 확인이다.
  실제 사람의 이해도 측정, 실제 Windows WSL2·16GB PC 검증은 아직 남아 있다.

원본 실행 기록은 `.cache/literature-pytest.{log,xml}`과
`.cache/literature-browser.{log,xml}`에 있다. 이전 Psi4 8개 비교는 아래 기록을 유지하며,
이번 변경 후 그 8개를 다시 실행했다고 주장하지 않는다. 기존 사용자 계산이 없는 것을
확인한 뒤 로컬 미리보기 서버를 0.3.1로 재시작했다. 외부 게시·업로드는 하지 않았다.

## v0.2 검증 기록

2026-11-14(한국 시간), Linux에서 전체 pytest **129개가 48.09초에 통과**했다. 실패·건너뜀은 없고 Starlette의 httpx 사용 관련 deprecation 경고가 있었다. 물의 기저 비교 실험, 기존 분자·주기계·RHF, 실행 관리 검사를 포함한다. 세 기저의 실제 큐 계산은 고정 입력의 직접 PySCF 호출과 에너지 `1e-8 Eh` 이내로 일치했다.

브라우저에서는 새 학습 실험의 서로 다른 시나리오 **5개**, 기존 회귀 **4개(32.0초)**의 통과를 확인했다. 신규 검사의 첫 실행에서 발견한 화면 전환 resize 오류를 수정하고 관련 2개 시나리오를 다시 실행했다. 아홉 검사를 한 번에 측정한 시간으로 합산하지 않는다. Ruff와 TypeScript·Vite 빌드도 통과했다. 처음 전체 검사에서 드러난 기존 TDA 종속성 기준 문제는 아래 응답 풀이기 항목에 수정 근거를 기록했다.

구현 순서와 세부 검사, 실제 계산값은 [v0.2 개발 기록](development-v02.md), 실제 화면은 [기저 비교 화면](images/basis-experiment.png)을 참고한다. 이번에 추가한 계산 엔진이나 외부 의존성은 없으며 앱 버전만 0.2.0으로 올렸다. 실제 Windows WSL2와 독립 엔진 비교는 여전히 미검증이다.

## 재현 명령

저장소 루트에서 잠금 파일의 의존성을 설치하고 실행한다.

```bash
uv sync --frozen
npm --prefix frontend ci
uv run pytest
npm --prefix frontend run build
```

브라우저 테스트는 별도 터미널에서 `./scripts/start.sh`로 서버를 실행한 뒤 수행한다.

```bash
npm --prefix frontend run test:e2e
```

현재 환경의 `/usr/bin/chromium`을 사용했다. 다른 Chromium 경로는 `CHROMIUM_PATH`로 지정한다. 시스템 Chromium이 없으면 frontend 폴더에서 `npx playwright install chromium`으로 설치한 브라우저를 사용한다. CI 워크플로에는 Chromium과 필요한 시스템 라이브러리 설치, 서버 준비 확인, 같은 브라우저 테스트 실행을 등록했다. GitHub의 실제 CI 실행 결과를 주장하는 것은 아니다.

브라우저 검증은 실제 계산을 실행하며 API 수치를 모킹하지 않는다. H₂는 XYZ 파일로, 결정은 CIF 파일로 가져왔고, 포름알데히드 TDA의 네 상태·스펙트럼·교육용 전이 애니메이션·NTO 격자를 확인했다. Vite 빌드는 성공했으나 상위 3Dmol 배포 파일의 `eval` 사용 경고가 출력되었다.

최종 설치 스크립트 재실행과 모식도·카탈로그 표시 조정 후에는 영향받은 여기 상태 브라우저 테스트를 다시 실행하여 1개가 14.3초에 통과했다. [최종 실제 화면](images/workspace.png)을 보존했다.

예제별 실제 실행 시간과 프로세스 최대 RSS를 기록하는 스크립트도 제공한다. 각 실행은 출력 폴더 아래 `runs/<UTC 시각-고유 ID>/`에 독립적으로 보존되고, 출력 폴더의 `report.json`은 최신 실행을 가리키는 보고서로 갱신된다.

```bash
uv run python scripts/baseline.py --output .quantum-lab/baselines
uv run python scripts/baseline.py --convergence --output .quantum-lab/convergence
```

각 사례는 **1스레드의 새 프로세스**에서 실행하며 `report.json`, 사례별 입력·결과·로그·측정값을 생성한다. 시간은 엔진의 `run()` 호출 구간으로, 인터프리터 시작과 엔진 모듈 import는 제외한다. 메모리 수치는 Python과 엔진 import를 포함한 프로세스 peak RSS이고 계산 배열만의 크기가 아니다. `--convergence`는 기저·격자·k점 변화에 대한 비교 입력을 실행하며, 설정 목록을 모두 실행했다고 물성의 수렴이 자동으로 증명되는 것은 아니다.

`examples/`에는 H₂·H₂O·포름알데히드 XYZ, 다이아몬드 CIF, 전체 예제 설정 JSON을 함께 제공한다. 화면에서 파일 가져오기를 시험하거나 동일한 입력을 API에서 실행할 수 있다.

### TDA/TDDFT 응답 풀이기의 수렴 설정

PySCF의 응답 풀이기는 보정 벡터의 제곱 노름을 `lindep`와 비교한다. 엄격한 잔차 허용오차를 지정했을 때 기본값이 유효한 작은 보정을 먼저 버려 요청한 수렴에 도달하지 못하는 경우를 확인했다. v0.1의 `(conv_tol * 0.1)²` 설정은 v0.2 전체 검증에서 `1e-22`까지 작아지면 거의 종속인 벡터를 남겨 잘못된 근과 미수렴을 일으키는 문제가 드러났다.

현재 어댑터는 사용자가 지정한 `conv_tol`과 `max_cycle`을 유지하고, `lindep = min(default_lindep, max(conv_tol², float64_epsilon))`로 수치 정밀도 하한을 둔다. 이 설정이 모든 입력의 수렴을 보장하지는 않는다. 요청한 잔차 기준을 만족하지 못하면 미수렴으로 반환한다.

실제 사용한 값은 결과의 `provenance.response_solver`와 이벤트에 기록한다. 회귀 테스트는 저장한 4개의 TDA 고유벡터에 별도로 구성한 응답 연산자를 적용하여 잔차를 확인한다. v0.2에서는 작은 포름알데히드 계산의 `1e-10`·`1e-12` 잔차 기준, 전체 응답 행렬을 직접 대각화한 근과의 일치도 추가 확인했다. 분자 테스트 12개가 11.66초에 통과했다. 수렴 플래그를 덮어쓰거나 요청한 허용오차를 완화하지 않는다. 같은 PySCF로 구성한 연산자를 사용하므로 독립 엔진의 물리적 정확도 검증과 구분한다.

## 과학적 승인 기준

동일 입력과 엔진 버전, 같은 격자·수렴 기준에서 다음을 검증한다.

| 항목 | 초기 허용오차 또는 확인 기준 |
| --- | --- |
| 분자 전체 에너지 | 직접 엔진 호출 대비 `1e-8 Eh` |
| 주기계 전체 에너지 | 직접 엔진 호출 대비 원자당 `1e-6 Eh` |
| 여기·밴드 에너지 | 동일 조건의 직접 엔진 호출 대비 `1e-4 eV` |
| 교육용 RHF | 에너지·밀도와 `CᵀSC = I` 확인 |
| 3D 밀도 | 유한 격자의 적분값과 전자 수 비교; 격자 해상도·범위에 따른 허용오차 기록 |
| 오비탈 | 겹침 행렬 기준 정규직교성, CUBE의 단위·인덱스 일치 |
| NTO | 가중치와 생성 관례, 상태 인덱스 확인 |
| 표시용 스펙트럼 | broadening 변경 시 원래 stick 에너지·세기 유지 |

다른 프로그램 간의 비교에서는 함수형 관례, 핵심 전자 처리, 기저 정의와 수치 적분이 다를 수 있으므로 위 어댑터 검증 허용오차를 그대로 적용하지 않는다. 현재 직접 PySCF와 어댑터의 비교는 독립 엔진 검증이 아니다.

빠른 작동 확인에 사용하는 작은 FFT 격자·Γ점은 연구 수준의 수렴 설정이 아니다. 수렴 비교는 목표 물성에 대해 기저·k점·격자를 독립적으로 증가시키는 별도 실험이다.

## 실패·재접속·시각화 시나리오

- 반복 제한을 낮춘 계산에서 그래프가 남아도 `unconverged`로 끝나는지 확인한다.
- 입력 전하·스핀·원소·기저 조합이 잘못되었을 때 실행 전에 설명 가능한 오류가 나오는지 확인한다.
- 대기 작업과 실행 중 작업을 각각 취소하고, 완료와 취소의 경쟁에서 터미널 상태가 뒤집히지 않는지 확인한다.
- SSE 연결을 끊었다 다시 연결해 순번 이후 이벤트를 중복 없이 복구하는지 확인한다.
- 서버 재시작 시 살아 있지 않은 계산을 실행 중으로 영구 표시하지 않는지 확인한다.
- 에너지가 오르내리는 이벤트를 그대로 렌더링하며 단조 감소로 보정하지 않는지 확인한다.
- 최적화 단계 클릭 시 해당 구조와 에너지가 연결되는지 확인한다.
- 밀도·오비탈·NTO 생성 작업이 같은 계산 큐를 사용하고 취소·오류를 표시하는지 확인한다.
- 분자와 결정에서 파일 입력→실행→차트·3D→재접속→내보내기를 실제 브라우저로 확인한다.
- 계산되지 않은 시간·수명·형광 양자수율을 UI가 계산 결과로 표시하지 않는지 확인한다.

## WSL2 확인표

아래 항목은 실제 Windows 장비에서 수행하기 전까지 미검증 상태다.

1. WSL2 Ubuntu의 Linux 파일시스템에서 새 체크아웃과 잠금 설치.
2. Windows 브라우저에서 로컬 서버 접속과 SSE 재접속.
3. H₂O와 다이아몬드 예제, CUBE 생성, 결과 다운로드.
4. 창·서버·WSL 종료 후 작업 상태와 데이터 보존 확인.
5. 실제 WSL 메모리 배정과 스레드 수에서 메모리·반응성 확인.

Linux 검증 결과를 WSL2 검증 결과로 대신 기재하지 않는다.
